# For the deployed Raspberry Pi rig only. Two things differ from a dev-machine install:
#
# 1. `python-gphoto2` needs the native `libgphoto2` C library, which is a Linux-only
#    dependency (`sudo apt install libgphoto2-dev` on Raspberry Pi OS) and will not
#    build on Windows/macOS dev machines. Without it, the app runs fine in simulated
#    mode (see README).
#
# 2. PySide6 is pinned here instead of pulling requirements.txt's unpinned entry
#    (pip can't resolve an unpinned and a pinned requirement for the same package
#    together, so this file depends on requirements-common.txt instead of
#    requirements.txt).
#    PySide6 >=6.8 ships Linux aarch64 wheels requiring glibc >= 2.39. On Raspberry
#    Pi OS Bookworm (glibc 2.36) that meant no installable wheel and a source build
#    (hours-long, frequently OOMs on a Pi 4), so this used to be pinned to 6.7.3,
#    whose wheel only needs glibc >= 2.31 but tops out at Python 3.12. The deployed
#    rig now runs Raspberry Pi OS Trixie (glibc 2.41, Python 3.13), which has no
#    wheel for 6.7.3 at all — hence 6.11.2, the latest version with a piwheels
#    aarch64 wheel as of writing. If you're deploying to a Bookworm-based Pi
#    (Python <=3.12, glibc 2.36), pin back to PySide6==6.7.3 instead.
PySide6==6.11.2
-r requirements-common.txt
gphoto2
